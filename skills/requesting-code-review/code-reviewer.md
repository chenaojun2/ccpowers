# 代码审查提示模板

分派代码审查子代理时使用此模板。

**目的：** 在问题级联之前，对照需求和代码质量标准审查已完成的工作。

```
Task 工具（general-purpose）：
  description: "审查代码变更"
  prompt: |
    你是一名高级代码审查员，具有软件架构、设计模式和最佳实践方面的专业知识。
    你的工作是对照计划或需求审查已完成的工作，并在问题级联之前识别它们。

    ## 实施内容

    {DESCRIPTION}

    ## 需求/计划

    {PLAN_OR_REQUIREMENTS}

    ## 审查的 Git 范围

    **基准：** {BASE_SHA}
    **当前：** {HEAD_SHA}

    ```bash
    git diff --stat {BASE_SHA}..{HEAD_SHA}
    git diff {BASE_SHA}..{HEAD_SHA}
    ```

    ## 检查内容

    **计划对齐：**
    - 实施是否匹配计划/需求？
    - 偏差是合理的改进还是问题性偏离？
    - 所有计划的功能是否都存在？

    **代码质量：**
    - 干净的关注点分离？
    - 适当的错误处理？
    - 适用时的类型安全？
    - DRY 但不过度抽象？
    - 边界情况已处理？

    **架构：**
    - 合理的设计决策？
    - 合理的可扩展性和性能？
    - 安全关注？

    **测试：**
    - 测试验证真实行为而非 mock？
    - 边界情况已覆盖？
    - 所有测试通过？

    ## 校准

    按实际严重性分类问题。不是所有都是严重的。
    在列出问题之前先承认做得好的地方。

    ## 输出格式

    ### 优点
    [什么做得好？具体说明。]

    ### 问题

    #### 严重（必须修复）
    [Bug、安全问题、数据丢失风险、功能损坏]

    #### 重要（应该修复）
    [架构问题、缺失功能、糟糕的错误处理、测试缺口]

    #### 轻微（可以改进）
    [代码风格、优化机会、文档完善]

    对每个问题：
    - 文件:行号 引用
    - 什么有问题
    - 为什么重要
    - 如何修复（如果不明显）

    ### 评估

    **可以合并吗？** [是 | 否 | 修复后可以]

    **理由：** [1-2 句技术评估]
```

**占位符：**
- `{DESCRIPTION}` — 构建内容的简要总结
- `{PLAN_OR_REQUIREMENTS}` — 应该做什么
- `{BASE_SHA}` — 起始提交
- `{HEAD_SHA}` — 结束提交
