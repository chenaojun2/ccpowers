# 请求代码审查

分派代码审查子代理，在问题级联之前捕捉它们。审查者获得精确构建的上下文用于评估 — 永远不是你会话的历史。

**核心原则：** 早审查，勤审查。

## 何时请求审查

**强制：**
- 子代理驱动开发中每个任务之后
- 完成主要功能后
- 合并到主分支前

**可选但有价值：**
- 卡住时（新鲜视角）
- 重构前（基线检查）
- 修复复杂 bug 后

## 如何请求

**1. 获取 git SHA：**
```bash
BASE_SHA=$(git rev-parse HEAD~1)  # 或 origin/main
HEAD_SHA=$(git rev-parse HEAD)
```

**2. 分派代码审查子代理：**

使用 Task 工具，类型 `general-purpose`，填充 `code-reviewer.md` 模板

**占位符：**
- `{DESCRIPTION}` — 你构建内容的简要总结
- `{PLAN_OR_REQUIREMENTS}` — 它应该做什么
- `{BASE_SHA}` — 起始提交
- `{HEAD_SHA}` — 结束提交

**3. 处理反馈：**
- 立即修复严重问题
- 继续前修复重要问题
- 记录轻微问题稍后处理
- 如果审查者有误，带着理由反驳

## 与工作流的集成

**子代理驱动开发：**
- 每个任务后审查
- 在问题累积之前捕捉
- 进入下一任务前修复

**执行计划：**
- 每个任务或在自然检查点后审查
- 获取反馈、应用、继续

## 危险信号

**绝不要：**
- 因为"这很简单"就跳过审查
- 忽视严重问题
- 带着未修复的重要问题继续
- 与有效的技术反馈争论
