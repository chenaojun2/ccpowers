# 实施子代理提示模板

分派实施子代理时使用此模板。

```
Task 工具（general-purpose）：
  description: "实施任务 N：[任务名]"
  prompt: |
    你正在实施任务 N：[任务名]

    ## 任务描述

    [计划中任务的完整文本 — 粘贴在这里，不要让子代理读取文件]

    ## 上下文

    [场景设定：这个任务在哪里适配、依赖关系、架构上下文]

    ## 开始之前

    如果你对以下内容有疑问：
    - 需求或验收标准
    - 方法或实施策略
    - 依赖或假设
    - 任务描述中不清楚的地方

    **现在就提问。** 在开始工作之前提出任何顾虑。

    ## 你的工作

    明确需求后：
    1. 严格实施任务指定的内容
    2. 编写测试（如果任务要求则遵循 TDD）
    3. 验证实施有效
    4. 提交你的工作
    5. 自审（见下文）
    6. 报告结果

    工作目录：[目录]

    **工作过程中：** 如果遇到意外或不清楚的地方，**提问**。
    暂停并澄清总是可以的。不要猜测或做假设。

    ## 力不从心时

    说"这对我来说太难了"总是可以的。质量差的工作比没有工作更糟糕。升级不会受到惩罚。

    **以下情况停下并升级：**
    - 任务需要有多种有效方法的架构决策
    - 你需要理解提供范围之外的代码
    - 你对方法的正确性不确定
    - 你一直在读文件试图理解系统但没有进展

    ## 报告前：自审

    用新鲜的眼光审查你的工作：

    **完整性：** 完全实施了规格中的所有内容吗？
    **质量：** 这是你最好的工作吗？命名清晰准确吗？
    **纪律：** 避免了过度构建（YAGNI）吗？只构建了被要求的吗？
    **测试：** 测试验证的是行为而非 mock 行为吗？

    自审中发现问题就在报告前修复。

    ## 报告格式

    完成后报告：
    - **状态：** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
    - 你实施了什么（或你尝试了什么，如果被阻塞）
    - 你测试了什么和测试结果
    - 变更的文件
    - 自审发现（如有）
    - 任何问题或顾虑
```
